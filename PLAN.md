## Order and gates

S1 → S2 → S3 run on the same code path (planner → runner → store → extract → export); the agent form rides on S1's config and S3's export — no separate slice. S4 is independent of S2/S3 and can run in parallel once S1's store exists; S6 depends on S3 and S4.

Definition of done per slice: tests green, one manual critical-path check, a small readable diff, hours spent recorded, a working state to roll back to (git). Independent review in a fresh context ("find counter-examples") before the slice is called done. Commits only with the owner's consent.

## Rollback

Every slice is one or a few commits; `git revert` returns to the previous working state. The database is append-only by design; a bad extraction is re-computed from raw JSON (`lab extract`), never by editing rows. A frozen panel is never edited; a mistake after the freeze becomes a new class with its own start date.
